# Flux Setup Guide (from practice)

## Prerequisites

- Kubernetes cluster running (e.g., minikube)
- `flux` CLI installed:
  ```bash
  curl -s https://fluxcd.io/install.sh | sudo bash
  flux --version
  ```
- GitHub **classic** personal access token with `repo` scope:
  - Go to GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic)
  - Scopes: `repo`, `workflow`
  - Classic tokens work on all repos — **fine-grained tokens** often fail with `permission denied` unless you explicitly attach the repo to the token

---

## Step 1: Bootstrap Flux

This installs Flux into your cluster and creates the first sync:

```bash
export GITHUB_TOKEN=ghp_xxxxxxxxxxxxxxxxxxxx

flux bootstrap github \
  --owner=zacknguyn \
  --repository=NguyenQuangPhong-aws-accelerator-p2 \
  --branch=main \
  --path=cloud/w9/day-a/flux-app \
  --personal \
  --token-auth
```

- `--owner` — your GitHub username
- `--repository` — repo name
- `--path` — folder Flux will watch
- `--personal` — single user (no org)
- `--token-auth` — use the token instead of SSH (required with PAT)

### What bootstrap does

| Step | What happens |
|------|-------------|
| 1 | Clones the repo |
| 2 | Generates Flux CRDs + controller manifests |
| 3 | Commits them to your repo under `flux-app/flux-system/` |
| 4 | Pushes to remote |
| 5 | Installs Flux controllers into your cluster |
| 6 | Creates `GitRepository` + `Kustomization` CRDs in `flux-system` namespace |

The default Kustomization is named **`flux-system`** (not `flux-app`).

## Step 2: Verify Flux is Running

```bash
flux check                     # Health check
kubectl get pods -n flux-system  # Should show 4 controllers running
flux get kustomizations        # List synced kustomizations
```

Expected output:
```
NAME        REVISION          SUSPENDED  READY  MESSAGE
flux-system main@sha1:...     False      True   Applied revision: main@sha1:...
```

## Step 3: Add Your App Manifests

Your `flux-app/` folder should look like:

```
cloud/w9/day-a/flux-app/
├── deployment.yaml
├── service.yaml
├── kustomization.yaml          # Your Kustomize config
└── flux-system/                # Auto-generated by bootstrap (don't edit)
    ├── gotk-components.yaml
    └── gotk-sync.yaml
```

### deployment.yaml

Just like the ArgoCD version — minimal YAML, `commonLabels` will inject the rest:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 2
  selector:
    matchLabels: {}
  template:
    spec:
      containers:
        - name: nginx
          image: nginx:latest
          ports:
            - containerPort: 80
```

### service.yaml

```yaml
apiVersion: v1
kind: Service
metadata:
  name: my-app
spec:
  ports:
    - port: 80
      targetPort: 80
  type: ClusterIP
```

### kustomization.yaml

**Important:** Must include `commonLabels` — without it, Kustomize won't inject `spec.selector.matchLabels` and the Deployment will be invalid:

```yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
  - deployment.yaml
  - service.yaml

commonLabels:
  app: my-app
```

## Step 4: Push and Watch it Sync

```bash
git add cloud/w9/day-a/flux-app/
git commit -m "[W9-D1] Add Flux app manifests"
git push origin main
```

Flux reconciles every few minutes automatically. Or force sync:

```bash
flux reconcile kustomization flux-system
```

Check status:

```bash
flux get kustomizations
kubectl get pods
```

---

## Step 5: Test a Change (PR + Merge)

Flux doesn't have a "plan on PR" built in — you use `flux diff` manually:

```bash
# Create a branch, make change
git checkout -b test-flux
# edit deployment.yaml replicas: 3
git add .
git commit -m "Test change"

# Preview what will change
flux diff kustomization flux-system --path cloud/w9/day-a/flux-app

# Merge
git checkout main
git merge test-flux
git push origin main
```

Flux auto-syncs the merge.

## Common Fixes We Hit

| Problem | Fix |
|---------|-----|
| `flux bootstrap` push fails with `authorization failed` | Use a **classic** token, not fine-grained. Add `--token-auth`. |
| `flux reconcile kustomization flux-app` → not found | The bootstrap names it **`flux-system`**, not `flux-app`. |
| Deployment error: `spec.selector: Required value` | Add `commonLabels` to `kustomization.yaml`. |
| Deployment error: labels don't match selector | `commonLabels` handles this — remove manual labels from `deployment.yaml`. |

## Comparing ArgoCD vs Flux

| Action | ArgoCD | Flux |
|--------|--------|------|
| Install | `kubectl apply -f manifests` | `flux bootstrap` |
| Watch a repo folder | `Application` CRD (create manually) | `GitRepository` + `Kustomization` (auto-created by bootstrap) |
| Sync | Auto-sync in CRD or `argocd app sync` | Auto-reconciliation every few minutes |
| Force sync | `argocd app sync my-app` | `flux reconcile kustomization flux-system` |
| Diff/plan on PR | GitHub Actions on pull_request | GitHub Actions with `flux diff` |
| UI | Built-in web UI | CLI only |
| Rollback | `git revert` + auto-sync | `git revert` + auto-reconcile |
| Auth for CI token | `argocd account generate-token` | GITHUB_TOKEN env var |
| Key feeling | "I manage a CRD pointing to my code" | "I bootstrap once, then just push" |

## Clean Up: Destroy Everything

### Option A: Remove Flux from cluster only

```bash
flux uninstall
kubectl delete namespace flux-system
```

Flux is gone. Your repo and app manifests remain.

### Option B: Remove Flux + delete cluster resources

```bash
# 1. Delete everything Flux deployed
kubectl delete deploy my-app --ignore-not-found
kubectl delete svc my-app --ignore-not-found

# 2. Uninstall Flux
flux uninstall
kubectl delete namespace flux-system

# 3. Delete bootstrap files from repo (optional)
rm -rf cloud/w9/day-a/flux-app/flux-system/
git add cloud/w9/day-a/flux-app/
git commit -m "[W9-D1] Remove Flux bootstrap files"
git push origin main
```

### Option C: Nuke everything (cleanest)

```bash
# 1. Uninstall Flux
flux uninstall

# 2. Delete all Flux-related namespaces + CRDs
kubectl delete namespace flux-system --wait
kubectl get crd | grep flux | awk '{print $1}' | xargs kubectl delete crd

# 3. Delete the flux-app folder from repo
rm -rf cloud/w9/day-a/flux-app/
git add cloud/w9/day-a/flux-app/
git commit -m "[W9-D1] Remove Flux experiment"
git push origin main

# 4. Verify
kubectl get pods
```
